Fig. 3.1 — Pipeline architecture and evaluation layer. The main path (M3) runs left to right through four processing stages: SVI–building pairing, visual attribute inference (type / construction year / floor count), deterministic TABULA archetype lookup yielding envelope U-values with per-value provenance, and downstream feature assembly. The control route (M1, blue) enters the pipeline at exactly one point — it replaces the inferred attributes with registry reference attributes and is otherwise identical downstream, so any performance difference is attributable to the attribute source itself (§4.1.2). The end-to-end route (M2, orange) maps facade crops directly to the EPC endpoint without attribute or archetype mediation; it is a parallel comparator, not a step of the archetype pipeline. Evaluation is defined separately from processing: binary EPC screening is the primary task, 7-class EPC prediction is retained as a diagnostic of the information ceiling under fine-grained labels, LOCO tests cross-city generalisation, and the H’tr check tests the physical consistency of the substituted thermal parameters. Grey chips mark external data sources and the feature tiers admitted downstream (§3.5).
