# 2026.05.21 — Stage 0 SVI Manifest + Stage 0.5 Three-City 3D BAG Fill-In

## Motivation

The thesis three-stage framework (Stage 1 visual attribute extraction / Stage 2 GT field
ablation / Stage 3 route comparison) is finalised in `doc_processed/spec/thesis_formal_spec.md`.
This work covers two Stage 1 prerequisites:

1. **Stage 0** — consolidate the per-cell OpenFACADES cropped building images across all four
   cities into a single manifest, link `pid_*_bdid_*.png` filenames to BAG `pand_id`, and apply
   the cap-8 rule (at most eight views per building).
2. **Stage 0.5** — backfill the Utrecht / Rotterdam / Amsterdam joined tables with 3D BAG so
   that `b3_bouwlagen` (floors GT) is present. Delft was already a three-source join; the
   other three cities had only BAG + EP-Online. Stage 1's three heads (type / year / floors)
   require this.

## Setup / Scope / Parameters

### Stage 0: SVI manifest

- New module: `src/svi_manifest.py`
- Scans `data/openfacades_output/phase_c_<city>_grid/cells/*/output/02_img/individual_building/pid_*_bdid_*.png`
- Regex parse: `pid_<panorama_id>_bdid_<openfacades_building_id>.png`.
  **`pid_` is the Mapillary panorama ID, NOT a BAG `pand_id`.**
- Utrecht / Rotterdam / Amsterdam lacked `bag_openfacades_id_mapping.csv`, so the manifest
  builder calls `src/vlm_pipeline.py::spatial_join_footprints_to_bag()` on the fly and caches
  the result to `merged/bag_openfacades_id_mapping.csv` per city.
- Cap-8 selection keys (from `merged/aov.csv`): `aov_geo` descending (angle of view of the
  building, degrees), then `distance` ascending (metres to building centroid).
- Output: `data/processed/svi_manifest.parquet`.

### Stage 0.5: 3D BAG fetch for three cities

Edits to `configs/utrecht.yaml`, `configs/rotterdam.yaml`, `configs/amsterdam.yaml`:

- `pipeline.use_3dbag: false → true`
- `data_paths.joined_output`: keep the legacy `bag_ep_joined.parquet` path untouched; add a
  new `bag_3dbag_ep_joined.parquet` path.
- Add `data_paths.lod2_output`.
- Add `wfs.bag3d_url` / `bag3d_layer` / `bag3d_page_size`.
- Add `lod2` block with `rmse_quality_threshold: 1.0` and `floor_height_default: 3.0`.

Run per city: `uv run python -m src.data_loader --config configs/<city>.yaml` → `lod2_features`
→ `tabula_matcher`.

## Issues / Bug Fixes

### Bug #1: `run_step1()` skipped the tiled BAG fetch path

`src/data_loader.py:500` (three-source path) used `fetch_bag_pand` (single-bbox request).
The PDOK BAG WFS refuses pagination beyond ~51k features. Utrecht / Rotterdam / Amsterdam
all have bboxes far larger than Delft, so BAG was being truncated at 50k and the EP-Online
inner-join ended up nearly empty.

First-pass results were:
- Utrecht: 1,733 buildings (expected ~20k)
- Rotterdam: 0 buildings (AssertionError `min_buildings >= 50`)
- Amsterdam: 0 buildings

**Fix**: switch to the existing `fetch_bag_pand_tiled()` (already used in the two-source
`run_step1_bag_ep` path).

### Bug #2: `documentdatum` mixed-type column rejected by pyarrow

`pyarrow.lib.ArrowTypeError: object of type <class 'str'> cannot be converted to int`.
The same BAG record returns `documentdatum` as a `str` from some tiles and an `int` from
others. After `pd.concat` the column is `object` dtype but mixed underneath, and pyarrow
cannot pick an arrow type. Utrecht passed (single tile, uniform), Rotterdam / Amsterdam
hit the bug because of multi-tile fetches.

**Fix**: in `validate_and_save()`, before `to_parquet`, coerce all non-geometry `object`
columns to `str` and keep NaN as `None`.

### Retention strategy for legacy files

The old two-source `bag_ep_joined.parquet` is untouched (different filename). The old
`residential_tabula_matched.parquet` (no floors) **is overwritten** by the new three-source
version, which is a superset (adds floors and 3D-derived columns).

### Manifest pand_id gap

Manifest 10,104 vs GT 10,090 = 14 unmatched. Of those, 6 are dropped by
`lod2_features.remove_outliers()` for `volume <= 0` (1 + 1 + 4 across cities), and 3 are
dropped by `tabula_matcher` for unmapped archetype (1 + 0 + 2). The remaining 5 fall out at
other join stages. Total loss is < 0.15 %; not blocking.
