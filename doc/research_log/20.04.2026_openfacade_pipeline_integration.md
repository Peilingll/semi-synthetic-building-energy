### Three install / runtime blockers

| # | Blocker | Resolution |
|---|---|---|
| 1 | `streetlevel>=0.6` pulls in `pyfrpc`, whose Cython C extension requires MSVC Build Tools (not installed on this Windows machine) | Pinned `streetlevel==0.5.0` via pip constraint; 0.5.0 does not depend on pyfrpc. zensvi's Mapillary downloader path is unaffected |
| 2 | `OpenFACADES/src/openfacades/footprint/downloader.py:70-71` used the osmnx < 2.0 `features_from_bbox(bbox=[N,S,E,W])` signature, but zensvi requires `osmnx>=2.0`. Result: bbox interpreted as invalid bounds, process consumed 8 GB RAM attempting to fetch a very large area | Replaced with `ox.features_from_bbox(tuple(bbox), tags)`, passing `(left, bottom, right, top)` WGS84 tuple directly |
| 3 | osmnx 2.0 renamed the OSM identity column from `osmid` to `id`. `downloader.py`'s `selected_columns` filter listed only `osmid`, so after `reset_index` the `id` column was dropped and `building_id` became null for 68/69 footprints | Added `'id'` to `selected_columns`; `col_names` already mapped `'id' → 'building_id'` |

Both downloader.py patches were applied to the local `D:/ITBE/Thesis/OpenFACADES/` clone. The clone is outside this repo, so upstream `git pull` may revert the patches. An upstream PR is warranted.

### Two independent acceptance dimensions

**Dimension 1: ID linkage — 8/8**

All 8 ground-truth pand_ids in the Delft bbox matched to an OpenFACADES `building_id` via centroid-containment spatial join. Every match came from OSM (no Overture tie-break needed). `building_id ↔ pand_id` strategy is validated on Dutch data.

**Dimension 2: Usable facade imagery — 0/8**

Not a single one of the 8 ground-truth buildings has a cropped facade image. Reason: OpenFACADES uses a default `buffer=30` m isovist radius, and the nearest Mapillary panorama for each ground-truth lies between 48 m and 333 m away.

| pand_id | Nearest Mapillary pano | Within 30 m? |

| 00014068 | 48.5 m | no |
| 00028625 | 147 m | no |

| 00026587 | 223 m | no |

Over the whole Delft bbox, only 49 of 1,811 OpenFACADES footprints (2.7 %) ultimately yielded a cropped image. The 336 Mapillary panoramas in the bbox cluster on a few arterial streets; residential blocks are effectively uncovered.

### Key findings

1. Spatial join on centroid containment is a stable linking method between OpenFACADES footprints (OSM/Overture) and BAG (pand_id) on Dutch data
2. Mapillary coverage on Delft residential streets is thin — this is a pipeline-level limitation, not a software bug
3. Thesis narrative will need to surface the real coverage rate of Mapillary-driven VLM across all residential pand_ids
