## 2. Six Research Directions Beyond Zero-Shot

### 2.1 Fine-tuning / Instruction tuning (most direct next step)
**Reference:** OpenFACADES (NAR73GL6)
- Fine-tuned open VLM on 31,180 globally-sourced labeled images outperforms zero-shot GPT-4o
- Stronger cross-cultural generalization than zero-shot baselines
- → Reproducible blueprint for our project

### 2.2 Reasoning-based VLM (CoT / RFT / self-supervised reasoning)
**Reference:** RISE (7IUSFXR8)
- Two-stage: RISE-CoT (closed-loop CoT generation with reward) + RISE-R1 (SFT warm-up + RFT)
- Self-supervised — no need for manually labeled CoTs
- Particularly suited to attributes that need multi-step inference (e.g. age, era classification)

### 2.3 Few-shot / In-context learning
**Reference:** OpenCity3D (38R38HTU)
- VLMs show meaningful zero/few-shot ability on building age, price, noise
- In-context examples can be tested as a low-cost intermediate step before fine-tune

### 2.4 Semi-supervised + geometric priors
**Reference:** Li et al. (2E49CEVT)
- Teacher–Student with GIS geometry as pseudo-label corrector
- mAP +4.3–4.8% with only 10% labeled data
- Resonates with our BAG-based filtering — but as a *training* paradigm, not just inference

### 2.5 Specialized backbone fine-tune (single-attribute SOTA)
**References:** Liu & Abbasabadi (Swin ViT, material), De Simone (SegFormer, WWR), Suppa (YOLOv9, WWR), Zhong (SAM, footprint)
- Often beat VLMs on single fine-grained tasks
- Trade-off: lose semantic captioning and multi-attribute capability

### 2.6 Multi-modal fusion
**Reference:** Mayer et al. (BAQP2QJ4)
- SVI + aerial + footprint + LST → EPC classification
- Macro-F1 64.64%, +14 points over k-NN baseline
- Suggests aerial / LST as complementary inputs to OpenFACADES output

## 3. Deep-Dive Q&A

### 3.1 OpenFACADES — what / why / how to inherit

**Annotation scope (not residential-specific):**

| Attribute | Categories |
|---|---|
| Type | apartments, house, retail, office, hotel, industrial, religious, education, public, garage (10) |
| Surface material | metal, glass, brick, stone, concrete, wood, plaster (7) |
| Age | numeric |
| Floor count | numeric |
| Feature description | free-form caption (ChatGPT-4o generated) |

**Annotation lineage:**
- Type / age / floor / material → harvested from OSM tags (crowdsourced, exists)
- Caption → auto-generated by ChatGPT-4o per image
- Bound together as `(image, OSM attributes, GPT-4o caption)` triples

**Inheritance options (instead of full reproduction):**

| Mode | Action | Compute |
|---|---|---|
| (i) Direct inference | Load fine-tuned weights, run on Delft images | 1 inference GPU |
| (ii) LoRA fine-tune | 200–500 Delft images + BAG labels, 1–3 epochs LoRA | 1× 24 GB GPU, hours |
| (iii) Full fine-tune | Rarely needed | Multi-GPU |

**Differentiation vs OpenFACADES** (where we add value):
- Residential-specific attributes (WWR, glazing %, roof type, chimney, insulation evidence)
- Alignment with EPC / energy ground truth (they did not touch energy)
- Dutch typology (rijwoning, vrijstaand, twee-onder-een-kap…)

→ Not "reproduce", but **"inherit + extend toward residential energy"**.

### 3.2 SFT vs RFT vs CoT (RISE terminology)

| Term | What it is | RISE usage |
|---|---|---|
| **SFT** (Supervised Fine-Tuning) | Train on (image, label) with cross-entropy / token loss; learns the answer, not the reasoning | Stage 2 step 1: warm-up on high-quality CoT subset |
| **RFT** (Reinforcement Fine-Tuning) | RL-based optimization (e.g. GRPO) using reward (IoU, accuracy); model produces think+answer | Stage 2 step 2: full-data RFT, outputs `<think>...</think><answer>...</answer>` |
| **CoT** (Chain of Thought) | Written-out reasoning narrative tying visual cues to the answer | Stage 1 RISE-CoT: closed-loop generation + verification |

**RISE's clever bit — no human-labeled CoT needed:**
1. VLM is given image + ground-truth label, asked to justify ("why this answer?") with leakage forbidden
2. A second VLM reconstructs the label from CoT + image
3. Reconstruction accuracy = CoT quality score → high-quality subset feeds SFT

### 3.3 Three CoT escalation paths

| Path | Description | Cost |
|---|---|---|
| (A) Pure prompt CoT | Zero-shot CoT prompt template | Afternoon — already tested, age accuracy poor |
| (B) Few-shot CoT | 2–4 in-context examples with CoT | No training |
| (C) RISE-style training | Auto CoT + SFT warm-up + GRPO RFT on small VLM (Qwen2-VL-2B / InternVL-2B) | 1× A100 40 GB, 1–3 days |

→ For thesis: **(A) is mandatory baseline**, **(C) is core contribution candidate**.

### 3.4 Are zero-shot / few-shot / CoT all "prompt engineering"?

| Method | Modifies weights? | Category |
|---|---|---|
| Zero-shot | ❌ | Prompt engineering |
| Few-shot (in-context) | ❌ | Prompt engineering |
| CoT prompting | ❌ | Prompt engineering |
| **SFT** | ✅ | Fine-tuning (gradient descent) |
| **RFT / RLHF / GRPO** | ✅ | Fine-tuning (reinforcement learning) |
| LoRA / QLoRA | ✅ (adapter) | Parameter-efficient fine-tuning |
| RAG | ❌ (external store) | Retrieval-augmented |

→ "Beyond zero-shot" splits along two axes: **change prompt** (cheap, lower ceiling) vs **change weights** (expensive, higher ceiling).
- OpenFACADES = SFT path
- RISE = SFT + RFT with self-supervised CoT
- Current Gemini API zero-shot = bottom of the prompt axis

### 3.5 Semi-supervised vs current geospatial filtering

**Current pipeline:** geospatial filter (BAG + OSM) → residential subset → zero-shot VLM.
This is `data curation`, **not training**.

**Li et al.'s semi-supervised (different paradigm):**
1. Train Teacher on the 10% labeled images
2. Teacher generates pseudo-labels for the 90% unlabeled
3. Student trains on (10% true) + (90% pseudo)
4. EMA updates Teacher

**Their innovation — geometry-aware:** GIS footprint function attribute is used to *correct* pseudo-label categories (auto-supervision source), not just as a filter.

| Stage | Current | Li route |
|---|---|---|
| Geometric data role | Filter to residential → feed zero-shot VLM | Filter + correct pseudo-label categories |
| Training data | None (no training) | 10% labeled + 90% pseudo, jointly trained |
| Goal | Inference only | Train a better facade detector |

**Adoptable insight even without full SSL:**
- Use BAG `bouwjaar` to auto-validate / correct VLM age predictions
- Use BAG attributes to auto-generate pseudo-CoT ("Dutch terraced house from 1965, expected brick facade…") for RISE
- Upgrade BAG from filter → supervision signal

## 4. The Netherlands BAG Paradox (Thesis-critical)

> "If the pipeline depends on BAG, does it generalize to places without BAG?"

Three framings (use A + C combined for strongest narrative):

**Framing A — Train-rich, Deploy-sparse (OpenFACADES logic):**
> The Netherlands has BAG → use it as supervision oracle to train. Deploy the trained VLM in cities without BAG (Jakarta, Lagos, Athens). BAG required at training time only, not inference.

**Framing B — Validation, not Dependence:**
> Pipeline only consumes street view at inference. BAG is the validation ground truth that proves prediction accuracy at scale — a luxury other cities cannot afford. Deployment elsewhere drops BAG entirely.

**Framing C — Transfer learning experiment:**
> Train on Delft → test on a non-BAG city → report cross-city accuracy drop. The transfer experiment itself is the contribution.

## 5. Differentiation From OpenFACADES (Thesis Contribution Angles)

| Dimension | OpenFACADES | This thesis |
|---|---|---|
| Task | Generic buildings (10 types incl. office/retail) | Residential typology focus |
| Geography | 7 mixed-continent cities | Delft / Netherlands residential |
| Label source | OSM crowdsourced (low coverage, noisy) | **BAG (national register, ~100% coverage, authoritative)** |
| Attributes | type, material, age, floor | + WWR, roof type, energy-relevant evidence |
| Downstream | Building description | **EPC / UBEM linkage end-to-end** |

**Key insight on data quality:**

OpenFACADES caveats we improve on:
- OSM tag missing-rate handled by per-attribute masking → material has fewer effective samples; lower accuracy than type
- ChatGPT-4o captions are auto-generated → potential hallucinated patterns the fine-tuned model inherits

**Our advantage:**
- BAG `bouwjaar`, `gebruiksdoel`, `oppervlakte` ≈ 100% coverage, no missing-tag issue
- Captions can be **template-generated from BAG** ("A {type} built in {bouwjaar}, footprint {oppervlakte} m²…") — fully verifiable, no hallucinations
- Both supervision ends grounded in authoritative register

→ Thesis one-liner:
> "OpenFACADES proved VLM fine-tune feasibility on noisy OSM data; this work adopts Dutch BAG as a *register-grounded dual supervision* (hard labels + grounded captions), fine-tunes a residentially focused VLM, and validates predictions end-to-end through UBEM-simulated EPC."

## 6. Recommended Thesis Path

```
Phase 1 — Baseline establishment (current)
  Zero-shot Gemini on OpenFACADES-extracted Delft images
  → Reveals which attributes work (material OK) and which fail (age weak)

Phase 2 — Off-the-shelf transfer (low risk)
  Load OpenFACADES fine-tuned weights → re-run on Delft → compare accuracy
  No training, ~1 week

Phase 3 — Custom training (thesis core)
  BAG bouwjaar / gebruiksdoel as supervision, EPC as downstream validation
  Choose one:
    (a) LoRA SFT on Qwen2-VL-2B    ← safe bet
    (b) RISE-style RFT             ← high-contribution bet (if time/compute available)
```

**OpenFACADES weights as initialization + RISE training paradigm for age** — these are stackable, not competing.

## 7. Glossary Recap

- **Zero-shot:** model has not been trained on this task; use the pretrained model as-is
- **Few-shot / in-context:** add examples in the prompt without weight updates
- **CoT prompting:** ask model to reason step-by-step in the prompt; no weight updates
- **SFT:** supervised fine-tuning; cross-entropy on (input, label) pairs; updates weights
- **RFT:** reinforcement fine-tuning; reward-driven gradient updates (e.g. GRPO)
- **LoRA:** parameter-efficient fine-tuning via low-rank adapter; ~0.1–1% of params
- **Domain adaptation:** fine-tune on a target distribution different from pretraining
- **OOD / cross-domain:** still zero-shot for the *task*, even if data distribution differs
