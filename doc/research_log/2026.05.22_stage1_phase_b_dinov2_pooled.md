# 2026.05.22 — Stage 1 Phase B: DINOv2 frozen + MLP, four-city pooled 5-fold + hold-out

## Motivation

Phase A (Delft 173 buildings, 1-fold smoke) validated the pipeline; Phase B
delivers the production version:

1. Scale to four cities (~10k buildings after manifest INTERSECT GT).
2. Switch to the standard 20% hold-out + 80% dev 5-fold CV split.
3. Add production-grade evaluation: class-weighted CE, bootstrap 95% CI,
   per-city / per-class slicing, hold-out one-shot final number.

Scope of this log: DINOv2 frozen baseline only. ResNet-50 / Swin-T / Gemini
zero-shot / LOCO are deferred to Phase C.

## Environment

- conda env `D:\conda_envs\stage1-gpu` (torch 2.6.0+cu124, timm 1.0.27)
- RTX 4060 Laptop, 8 GB VRAM, CUDA 12.9 driver
- batch 32, num_workers 2, fp16 AMP, AdamW(lr=5e-4, wd=0.01), patience 10

## Data

- **Combined GT**: `data/processed/stage1_gt.parquet`, 124,784 residential rows
  (filters: gebruiksdoel contains woonfunctie, valid Energieklasse, Gebouwtype
  in GEBOUWTYPE_MAP, bouwjaar in [1800, 2025], num_floors in [1, 30]).
- **Training universe** (manifest INTERSECT GT): **10,086 buildings / 47,150 images**.
- Class distribution: AB 88.4 %, TH 9.8 %, SFH 1.3 %, MFH 0.5 % (severe imbalance).
- City distribution: Amsterdam 79 %, Rotterdam 14 %, Utrecht 4.8 %, Delft 1.7 %
  (Amsterdam dominant).
- `tabula_period` unified via `tabula_matcher.classify_period(bouwjaar)`
  (overrides Delft's legacy `build_period` so the column is consistent across
  the four cities).

## Split design

Two-stage StratifiedGroupKFold:

```
10,086 buildings (manifest INTERSECT GT)
  | Stage 1: SGKF(5).split() first fold = 20 % hold-out
  |   hold-out: 2,018 buildings (SHA256 prefix 7b877c7d4c066832)
  |   dev:      8,068 buildings
  | Stage 2: SGKF(5) inside dev = 5 folds (~1,613 val each)
```

Strata = `city x Gebouwtype x Energieklasse x tabula_period` (union of Stage 1
target and Stage 2/3 target — 320 unique strata). Group = `pand_id` prevents
image-level leakage. Stage 1/2/3 share the same hold-out.

## Model

DINOv2 ViT-B/14 frozen + MLP (spec §3.2.3 lower-bound baseline role):

- `timm.create_model("vit_base_patch14_dinov2.lvd142m", dynamic_img_size=True)`
  with 224 input (positional embedding interpolated from 37x37 to 16x16).
- Mean-pool over up to 8 images per building, MLP trunk 768→256+GELU+Dropout(0.3),
  three heads: building_type (4-class CE with inverse-frequency class weights),
  bouwjaar (MSE on standardized year), num_floors (MSE on standardized floors).
- Trainable parameters: ~198k (the 86.6 M backbone is fully frozen).

Class weights (computed per fold): SFH ~0.93, TH ~0.13, MFH ~2.93, AB ~0.014.

| Metric | Value | 95 % CI |
|---|---:|---|
| **type_acc** | **0.910** | [~0.893, 0.914] |
| **type_macro_f1** | **0.519** | [0.473, 0.561] |
| **year_mae** | **9.45 yr** | [8.83, 10.06] |
| **floors_mae** | **0.377** | [0.354, 0.404] |

**Hold-out macro_f1 (0.519) is 0.097 below the 5-fold dev mean (0.616)** while
type_acc and year_mae stay essentially flat. The fold-4 best checkpoint
over-fits to its own dev val; the hold-out number is the true generalisation
estimate.

The paper Table 1 should report the hold-out figure (or `mean ± std` from the
5-fold dev split) rather than mixing the two.

## Decisions and observations

1. Phase B pipeline ran end-to-end across 12 mini-commits; every acceptance
   criterion in the plan was met.
2. Scale dominance: the same frozen-backbone + MLP head, with 58x more data and
   class weighting, roughly doubles macro_f1 and cuts year MAE by two thirds.
3. B-shape over-fit recurs in every fold: train_acc climbs to 0.93-0.95 while
   val plateaus at 0.91 and val_loss rebounds. Patience-10 + class-weighted CE
   recover the best checkpoint reliably.
4. Fold variance (std 0.044, spread 0.115) is wider than ideal. Fold 1 best at
   epoch 7 never recovered, fold 3 trained the full 30 epochs to plateau at
   0.552. Likely small-strata effects and random seed sensitivity.
5. Hold-out vs 5-fold mean macro_f1 gap of 0.097 indicates the fold-4 best ckpt
   over-fits to its own dev val. Paper must pick one of the two as the
   headline number, not mix them.
6. Generalisability gap is large (Amsterdam acc 0.94 vs Utrecht 0.58). Phase C
   LOCO will quantify how much further this widens when the dominant city is
   removed from training.

## Next steps (Phase C decision)

Per the plan's "Phase B → C trigger" table:
- type_acc 0.910 > 0.75 ✓
- macro_f1 0.519 (hold-out) sits below 0.55; 5-fold mean 0.616 sits in the
  0.50-0.60 band.

Two viable paths:

- Path A: launch Swin-T full fine-tune (spec's expected winner) and see if
  hold-out macro_f1 crosses 0.6.
- Path B: debug DINOv2 first — try lr sweep / heavier augmentation / earlier
  patience — and see if 0.519 → 0.57 is reachable cheaply.

Suggested order, decoupling from GPU bottleneck:
- Run Gemini 2.5 Flash zero-shot first (~3 hr API time, no GPU). This gives
  the fourth Table-1 number cheaply and may already settle whether VLM
  zero-shot beats supervised CNN.
- Defer Swin-T full fine-tune (~80 GPU-hr) until after the paper structure is
  decided.
