## Amsterdam launch (optimised pipeline)

### Why optimise

Amsterdam grid: 1,160 cells, **567 residential**. n_resid distribution:
median 71, p25=9, p75=198 — long-tailed. Naive full run was projected at
35–40 h. Three optimisations applied:

1. **OpenFacades Patch #6**: `max_image_per_building=5 → 3`.
   - Stage-4 pano downloads and Stage-5 GroundingDINO inference both drop
     ~40 %, the dominant per-cell cost.
   - Matches the user's downstream "3–5 images/building" target; median of
     Delft/Utrecht/Rotterdam is already 3–6, so this is a yield-aligned cap,
     not a quality cut.
2. **Runner flag `--min-residential-per-cell 30`** to skip the long tail.
   - 207 of 567 (37 %) Amsterdam residential cells fall below this threshold.
   - Utrecht's tail (n_resid < 30) was almost entirely `no_pano_coverage` or
     transient failures — low expected loss.
3. **Runner `MAX_RETRIES_PER_CELL = 2 → 1`**.
   - The collection strategy is now "enough samples, then stop"; aggressive
     retry no longer worth the extra wall-clock.

Projected total runtime: **~24 h** (vs. 35–40 h baseline).

### Expected output

Extrapolating from Utrecht / Rotterdam scale:
- Done cells: ~100–130
- Total select images: 5,000–8,000 (with Patch #6 trimming ~40 % per cell)
- Unique buildings with imagery: 1,500–2,500
