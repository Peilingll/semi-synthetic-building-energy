# 2026-08-12 — M2 under LOCO split (fills the "LOCO never ran M2" gap)

## Motivation

Obj 3's conclusion could only state "end-to-end wins in-distribution, cross-city
behaviour untested". Pooled M2-DINOv2 beats M1 by +0.105 binary macro-F1
(0.597 vs 0.492); if that survived the city transfer, the attribute-mediated
route would be hard to defend.

## Setup

- New script `src/stage3/m2_loco.py`: identical protocol to the pooled headline
  (M2-DINOv2 aligned-cached: frozen DINOv2 embeddings + Stage1-style neural head
  768->256, class-weighted CE, best-of-5-folds by val macro-F1, restricted to
  the M1 common set). Only the split changes: LOCO train 2,075 (R+U+D),
  test 8,011 (Amsterdam).
- Embeddings reused from the pooled extract (dev + holdout union covers all
  10,086 buildings). Runtime: seconds per task on `stage1-gpu`.

## Final Data

| | 7-class mF1 | binary mF1 | binary ROC-AUC |
|---|---:|---:|---:|
| M2-DINOv2 pooled | 0.2131 | 0.5971 | 0.6614 |
| **M2-DINOv2 LOCO** | **0.1395** | **0.4991** | **0.5279** |
| M1 LOCO (reference) | 0.1429 | 0.4963 | 0.5282 |
| M3-DINOv2 LOCO (reference) | 0.1412 | 0.4904 | 0.5050 |

- M2's advantage over M1: pooled 7c +0.041 / bin +0.105 -> LOCO 7c **-0.003** /
  bin **+0.003**. The end-to-end advantage is in-distribution only.
- All three routes converge on the unseen city (binary AUC 0.505-0.528, near
  coin-flip). Image-route cross-city failure is shared; it just sits in
  different places (M3: year attribute, M2: the whole representation).
- Source-pool val f1 0.60 -> target city 0.499: transfer gap comparable to M3.

## Issues

- M2-ResNet50 full fine-tune under LOCO not run (hours of GPU; not essential —

- Note the second layer of the LOCO readout: even M1 (GT attributes) drops to
  AUC 0.528 on Amsterdam — pool homogeneity (94% AB|NL.01), not vision, so LOCO
  attribution must separate transfer failure from target-pool homogeneity.
