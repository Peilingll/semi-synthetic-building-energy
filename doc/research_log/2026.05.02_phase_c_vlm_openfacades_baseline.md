# 2026.05.02 — Phase C-VLM Phase 2: OpenFACADES FT-2B Baseline

## Goal

Run the off-the-shelf OpenFACADES fine-tuned VLM (`seshing/openfacades-internvl3-2b`) on
the 1,234 cropped Delft residential street-view images produced by Phase C-Image
(2026-05-01), and quantify per-attribute accuracy against BAG ground truth. This is the
"Phase 2" step in the thesis path documented in
`doc_processed/log/2026.05.01_vlm_facade_research_directions_zh.md` §6, the off-the-shelf
transfer baseline against which the upcoming custom Phase 3 fine-tune will be compared.

## Pipeline changes vs. Phase C-Image

1. **New file** `src/vlm_openfacades_inference.py` — single-GPU loader for the fine-tuned
   VLM. Mirrors the resume-on-image-name flow of `src/vlm_inference.py` (the Gemini-MVP
   wrapper).
2. **Verbatim training prompt** extracted from
   `D:/ITBE/Thesis/OpenFACADES/data/jsonl/train.jsonl` after running
   `train/get_train_data.py` (HuggingFace `seshing/openfacades-dataset`). Of the 58,942
   training conversations the most-frequent multi-attribute prompt (~19,443 examples)
   asks for an 8-field JSON with `building_type`, `alternate_building_type`,
   `building_age`, `floors`, `surface_material`, `alternate_surface_material`,
   `construction_material`, `alternate_construction_material`. We use this prompt
   verbatim — the alternative single-attribute prompts and the captioning prompts are not
   used.
3. **`InternVLChatLite`** (single-GPU class) — replaces `openfacades.vlm.InternVLProcessor`
   because the upstream `device_map='auto'` path triggers transformers' new
   `infer_auto_device_map`, which expects an `all_tied_weights_keys` attribute that the
   InternVL custom modeling code does not provide.
4. **Aggregator** `src/vlm_aggregate.py` — reads the per-image CSV and the
   `bag_openfacades_id_mapping.csv` (one-shot spatial join from
   `src/vlm_pipeline.py:spatial_join_footprints_to_bag` against the merged Phase C
   footprint), groups by `pand_id`, applies majority vote to categoricals and median to
   numerics, writes `data/processed/vlm_predictions_full.csv`.
5. **Evaluator** `src/vlm_evaluate_phase2.py` — joins aggregated predictions with the BAG
   `residential_tabula_matched.parquet` ground truth and reports per-attribute metrics.

## Environment hassle

The conda env `D:/conda_envs/openfacades` from Phase A had been pinned to dependencies
suitable for OpenFACADES Phase C-Image (Mapillary download, GroundingDINO). Loading the
fine-tuned VLM required five additional fixes:

| # | Error                                                              | Fix |
|---|--------------------------------------------------------------------|-----|
| 1 | `ModuleNotFoundError: 'decord'` from `openfacades.vlm.base` import | `pip install decord` |
| 2 | `ImportError: einops` (InternVL custom modeling) | `pip install einops timm sentencepiece protobuf` |
| 3 | `ValueError: device_map='auto' requires accelerate` | `pip install accelerate bitsandbytes peft` |
| 4 | `AttributeError: 'InternVLChatModel' object has no attribute 'all_tied_weights_keys'` (transformers 5.5.4 vs InternVL custom code) | Downgrade `transformers==4.37.2` (the version OpenFACADES `train/requirements.txt` pins) |
| 5 | `device_map='auto'` still hits the same `_finalize_model_loading` bug | Implement `InternVLChatLite` with plain `.cuda()` instead of `device_map='auto'` |

Conflict: `zensvi 1.4.7` requires `transformers>=4.40.0` and was downgraded to 4.37.2 too.
Acceptable here — zensvi is only used in Phase C-Image (Mapillary metadata + AoV), not
during VLM inference. Recorded in
`doc_processed/log/2026.05.01_vlm_facade_research_directions_zh.md` §13.

`FlashAttention2` is not installed (no MSVC build tools); InternVL falls back to eager
attention. Inference on RTX 4060 Laptop 8 GB averaged ~5.4 s/image, which was acceptable
for the 1,234-image run.

### JSON parse quirk

The fine-tuned model occasionally emits an empty key line (`,\n,\n`) between fields,
typically after `"floors": N,`. 342/1234 responses (27.7 %) had this quirk. The JSON parse
function was extended to collapse `,\s*,` → `,` and strip trailing commas before
`json.loads`. After the fix, all 1234 raw responses parsed successfully — no rerun
needed.

## Per-attribute results (165 pand_id evaluated)

### 1. Building type (coarse residential 2-class: AB vs. house)

- **73.6 % accuracy** restricted to predictions classified as residential (AB or house),
  N=110.
- **33.3 % of predictions are non-residential** (49 retail + 4 industrial + 1 education +
  1 office). The biggest single failure mode is the model labeling residential facades as
  `retail` — likely cropped images that show a ground-floor storefront mixed with
  upper-floor flats, or street-corner residences with shop signage.
- Confusion matrix:

| | predicted AB | predicted house |
|---|---|---|
| true AB (TABULA) | **44** | 5 |
| true house (TABULA) | 24 | **37** |

  - AB recall 89.8 %, precision 64.7 %
  - house recall 60.7 %, precision 88.1 %
  - The model over-predicts AB on houses (likely small terraced rows look like flats from
    cropped pano angles).

### 2. Construction year vs. BAG `bouwjaar`

| Metric | Value |
|---|---|
| MAE | **48.3 years** |
| Median absolute error | 25 years |
| Within ±10 y | 24.9 % |
| Within ±20 y | 44.9 % |

Very weak. Confirms the existing literature consensus and the
`vlm_facade_research_directions` doc §3.3 path C (RISE-style RFT for age) as the right
Phase 3 priority. Half the predictions are >25 years off; quarter are >50 years off.

### 3. Number of floors vs. 3DBAG `num_floors_estimated`

| Metric | Value |
|---|---|
| MAE | **0.81 floors** |
| Exact match | 32.7 % |
| Within ±1 | **89.1 %** |

Strong. OpenFACADES FT-2B handles floor counting well — no need for custom retraining on
this attribute. (One-floor-off is dominated by basements/half-stories that BAG and the
model count differently.)

### 4. Surface material distribution

No BAG ground truth, distribution check only:

| Predicted material | n | share |
|---|---|---|
| brick | 140 | 84.8 % |
| plaster | 20 | 12.1 % |
| glass | 4 | 2.4 % |
| wood | 1 | 0.6 % |

Plausible — Delft residential housing stock is dominated by brick with plaster facades on
some periods. Glass/wood at the long tail are likely the same buildings the type model
labeled as retail/industrial (storefront glass dominates the cropped frame).

## Implications for Phase 3

1. **Lock in age as Phase 3 target** — Year MAE 48.3 y is the obvious weakest link and
   matches the existing thesis differentiation argument. Use BAG `bouwjaar` as the
   100 %-coverage supervision oracle (vs. OpenFACADES's noisy OSM `start_date`).
2. **Floor counting needs no work** — 89 % within ±1 already, do not spend Phase 3 effort
   here.
3. **Type confusion is real but not the thesis focus** — 33 % non-residential
   misclassification is a Phase C-Image cropping artifact (groundfloor shop visible) more
   than a VLM problem. Either tighten the image crop in Phase C-Image, or treat the
   "non-residential" label as a discard signal during downstream aggregation, mapping
   only `apartments`/`house` predictions through to UBEM.
4. **Material has no BAG label** — keep brick-vs-other as a soft signal but do not run a
   formal accuracy comparison until manual labels exist for ~30 buildings.
5. **WWR still routed to SegFormer/SAM** (route 1 in the directions doc §10) — the FT
   model has nothing about WWR, confirming the original split decision.
