## 關鍵發現：Utrecht Mapillary 360° 覆蓋率 << Delft

對比 Delft Phase C：
- Delft 26 個 residential cell，9 個 `done` (有 pano 影像)，17 個 `failed`
  （回顧看，大概率多為「未被 Patch #5 區分的 no_pano_coverage」）。
- Utrecht top-2 highest density cell 已確定 0 pano。

OpenFacades 預設 `image_type="pano"` 只抓 360° 等距投影全景。Mapillary 的 360°
panorama 來自系統性 mapping 車隊（Tom-Tom、Bliksurvey 等），覆蓋通常集中在
特定走廊；一般手機/單眼拍攝不屬此類。Utrecht 在這個 filter 下可能近乎空白。

## 三條前進路線（待決定）

### A. 維持 `pano` filter，續跑全 Utrecht
- 預估 162 cells × 5 min（多數無 pano 跳過快）≈ 13 hr
- 風險：可能拿到 < 50 棟有影像；可能仍不足 ablation 樣本
- 優點：與 Delft pipeline 嚴格一致、可直接套用 InternVL3 fine-tuned model

### B. 放寬到 `image_type="both"`（pano + flat）
- 改 OpenFacades `prepare_mly_metadata()` 的 `kwarg = {"image_type": "both"}`
- 風險：flat image 視角窄、與 Delft training 分布不同 → fine-tuned VLM accuracy
  可能掉很多
- 優點：影像數可能 10× 以上
- 需要：cropping / AoV 邏輯重新驗證（aov_geo 計算對 flat image 是否合理？）

### C. 切換 Google Street View Static API
- Mapillary fail-safe；GSV 在荷蘭三大城覆蓋極好
- 風險：$7/1000 張、ToS 限制（不能 cache 久、不能 batch download）
- 優點：穩定、可保證有影像
- 需要：寫 GSV downloader、替換 OpenFacades stage 2-4
